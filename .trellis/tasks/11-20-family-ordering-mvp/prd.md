# 家庭点菜程序 MVP（v3）

> v2→v3 变更（2026-11-20 用户反馈）：① 微信推送整体后移（一期仅保证微信内浏览器可用，不做任何推送相关设计）；② 身份模型改钉钉式多租户：人与家庭分离，一个账号可加入多个家庭并随时切换；③ 菜单/分类/餐次维护需角色权限（admin），普通成员只能点菜。
> v1→v2 变更：菜单维护进一期；多家庭共用；餐次家庭自定义。

## Goal

多家庭共用的点菜 H5 应用，体验对标饭店扫码点餐：家人在各自手机（含微信内置浏览器）上浏览菜单、点菜，按家庭自定义的餐次实时汇总总单给做饭的人。参考钉钉的多租户身份模型——一个账号可属于多个家庭（自己家、父母家、亲戚家）并随时切换；菜单与餐次由家庭内管理员维护。以参考项目（location-tracking-platform）的 Trellis AI 工程流程开发。

## Background

- 仓库 `Family-Ordering` 为空仓起步：仅 Trellis v0.6.17 脚手架，无业务代码。
- 参考项目工程经验见 `research/location-tracking-platform-analysis.md`：技术栈 React 19 + antd-mobile / Express 5 + TS + Prisma + PostgreSQL + Vitest；时区、原子性、渲染期纯度等踩坑知识直接借鉴。
- 个人项目，非公司需求；预期多个家庭共用一个部署实例，且部分成员会同时属于多个家庭。

## Key Decisions

| 决策 | 结论 |
| --- | --- |
| 产品形态 | 家庭成员各自手机点菜（H5），实时汇总总单；做饭的人手机看单 |
| 身份模型（钉钉式） | **全局账号（用户名+密码）与家庭成员档案分离**：`user` 全局唯一，`family_member` 是 user 在某家庭内的档案（昵称+头像+角色）；一个 user 可加入多个家庭，应用内一键切换当前家庭 |
| 登录凭证 | **一期自建：用户名+密码**（免短信/免微信授权依赖，个人项目零外部成本；微信网页授权需认证服务号=企业主体，个人办不了）；注册即创建全局账号，再选择「创建家庭」或「凭口令加入家庭」。**二期路径已定**：拿到认证服务号后加「微信绑定」，老账号绑 openid 后微信内静默授权一键登录，用户名密码保留兜底，零迁移成本 |
| 家庭（租户） | 家庭口令全局唯一，用于「加入家庭」的准入；创建家庭者为该家庭 admin；各家庭菜库/成员/餐次/总单完全隔离 |
| 角色权限 | 两级：`admin`（菜单/分类/餐次维护、成员角色管理）与 `member`（点菜、看总单、维护自己的昵称头像）；admin 可将成员提升为 admin 或降级；允许一家庭多 admin |
| MVP 范围 | 核心点菜流程 + 菜单维护（admin）+ 家庭/餐次配置（admin）+ 多家庭账号体系；历史/爱吃榜、随机推荐、推送提醒进二期 |
| 部署 | **先本机，后上云**：开发期本机 `docker compose` 全栈运行（架构按公网设计：env 隔离、HTTPS 就绪）；服务器落位后按 `deploy/` 文档一键迁移上线（Caddy 自动 HTTPS）。家庭准入靠各自口令 |
| 代码托管 | GitHub 私有仓库：仅代码与 `.env.example`，`.env`/数据不入库；数据全部在服务器/本机 PostgreSQL（Docker 卷），配 pg_dump 备份脚本 |
| 技术栈 | Express 5 + TypeScript + Prisma + PostgreSQL（Docker）；React 19 + antd-mobile（Vite）；Vitest |
| 餐次周期 | 每家庭自定义：餐次=名称+时间窗（HH:mm，允许跨午夜），仅 admin 可维护；新家庭预置午餐/晚餐；按配置判定当前餐次，可手动切换 |
| 微信 | 一期仅保证微信内置浏览器可用（webview 适配、安全区）；**推送提醒、微信授权登录、openid 绑定整体二期再议** |
| 自定义菜 | 菜单没有的菜可输菜名直接点（快照式，不入菜库）；member 无菜单维护权限时的自然补充入口 |
| 实时性 | MVP 短轮询（≤10s），WebSocket/SSE 二期 |

## Requirements

### R1 账号与身份（钉钉式多租户）

- R1.1 注册：用户名+密码创建全局账号（用户名全局唯一，密码 bcrypt 存储）。
- R1.2 登录后进入「我的家庭」：可创建家庭（家庭名+设置口令，创建者成为 admin）或凭口令加入已有家庭；一个账号可加入多个家庭。
- R1.3 每个家庭内维护独立的成员档案（昵称+预置头像），默认取用户名，可按家庭各自修改。
- R1.4 应用内一键切换当前家庭（点菜/总单/菜单全部随切换刷新）；下次登录回到上次使用的家庭。
- R1.5 会话 token 载明 userId+当前 familyId+memberId；退出登录清除。

### R2 菜单浏览（全员）

- R2.1 按分类展示当前家庭菜品，显示菜名与简介。
- R2.2 菜品卡片上可直接加减份数。
- R2.3 微信内置浏览器打开体验正常（安全区、点击无延迟、iOS 键盘不遮挡）。

### R3 菜单维护（仅 admin）

- R3.1 分类增删改（改序）；分类下有菜品时禁删。
- R3.2 菜品增改删、上下架（下架不显示但历史总单不受影响）；同分类下菜名唯一。
- R3.3 维护入口在「管理」页，仅 admin 角色可见；member 调用维护接口一律 403。

### R4 点菜（全员，限本人）

- R4.1 当前餐次按本家庭餐次配置自动判定；无命中提示非点菜时段并允许手动选餐次。
- R4.2 成员对当前餐次加菜、删菜、调整份数，仅能修改自己的记录。
- R4.3 可输入自定义菜名加菜（不入菜库，总单中同样汇总）。
- R4.4 「我的点餐单」视图列出本人当前餐次所点菜品与份数。

### R5 餐次配置（仅 admin）

- R5.1 餐次增删改：名称、起止时间（HH:mm，支持跨午夜）、排序。
- R5.2 新家庭预置「午餐 / 晚餐」，可改可停用。
- R5.3 餐次停用为软删（enabled=false），历史数据保留。

### R6 成员管理（仅 admin）

- R6.1 查看当前家庭成员列表（昵称、头像、角色）。
- R6.2 调整成员角色（member↔admin）；不提供移除成员（MVP 从简，二期补）。

### R7 餐次总单（全员）

- R7.1 按餐次汇总全家人点菜：同名菜（含自定义菜名）合并计数，展示每道菜是谁点的。
- R7.2 总单页轮询刷新（≤10s）。
- R7.3 总单上的菜可「划掉」（置灰，不删数据），刷新后状态保持。
- R7.4 跨天自动滚动：每天每餐次一张新单，旧单保留（查看历史二期）。

### R8 数据与运维

- R8.1 种子数据：一个示例家庭（默认餐次、示例成员含 admin/member 各若干、4 分类约 24 道家常菜）+ 一个演示账号。
- R8.2 日期与餐次归属统一 Asia/Shanghai 时区工具，禁 `new Date('YYYY-MM-DD')` / `toISOString().split('T')`。
- R8.3 `docker compose up` 一键起全栈（本机即目标形态）；`deploy/` 成文：本机运行说明 + 上云迁移步骤（域名/Caddy HTTPS/env 配置）+ pg_dump 定时备份脚本。

## Acceptance Criteria

- [ ] 注册→创建家庭→以 admin 进入；另两账号凭口令加入同家庭，其中一个被 admin 提升为 admin 后可见「管理」页。
- [ ] 同一账号加入第二个家庭后一键切换：菜库/成员/餐次/总单完全隔离随切换刷新；越权访问他家庭资源被拒（403/404）。
- [ ] member 角色看不到管理入口，直接调菜单/餐次维护接口返回 403；admin 上下架菜品后菜单页即时生效，历史总单不变。
- [ ] 两成员在两台设备分别点菜，总单 10s 内合并显示双方菜品，同名菜合并计数并标注点菜人；划掉置灰刷新后保持。
- [ ] 修改餐次配置（如新增「夜宵 21:00–01:00」）后，处于该时间窗自动判定为夜宵；跨午夜判定正确。
- [ ] 自定义菜名加菜在总单中正常汇总；次日自动新单，昨日菜不混入。
- [ ] 微信内置浏览器真机走通：登录→点菜→看总单全流程，无布局/交互异常。
- [ ] `docker compose up` 后全栈可用；后端与前端 lint、type-check、Vitest 全绿（本地 CI 门禁）。
- [ ] 公网 HTTPS 部署文档成文，按文档可操作。

## Out of Scope（二期候选）

- 微信推送提醒、微信授权登录、小程序版本（用户确认整体后移）
- 历史总单查看、爱吃榜、「今天吃什么」随机推荐
- WebSocket/SSE 实时推送；菜品图片、搜索
- 移除成员/退出家庭、邀请链接（MVP 用口令准入）
- 忘记密码自助找回（MVP 记录运维重置脚本即可）

## Risks / Deferred

- **口令即家庭准入**：无邀请链接与成员审批，口令外泄即进入；家庭互信场景可接受，二期可加邀请码轮换。
- **自建账号体系**：用户名+密码自管，无短信/微信依赖；密码找回需运维脚本，家人忘记密码由 admin 侧联系部署者重置（MVP 从简）。
- 公网服务器落位未定 → 不阻塞验收（部署文档先行）。
- spec 模板回填 → 实现完成后进行（implement.md E5）。

## Technical Notes

- 分层沿用参考项目：后端 routes（薄）→ services（厚）+ Zod 校验 + 统一响应；前端 services 层统一 request 封装，组件禁止直接 fetch。
- 多租户要点：业务表挂 `family_id`；token 载 `{ userId, familyId, memberId }`；service 层强制按 familyId 过滤；admin 路由挂 `requireAdmin` 中间件。
- 本任务为复杂任务：`design.md` 与 `implement.md` 随本 PRD 一并评审。
