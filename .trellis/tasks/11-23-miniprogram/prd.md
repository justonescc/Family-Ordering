# 小程序化改造规划

## Goal

把现有「家庭点菜」H5 能力以 **Taro（React 语法）小程序** 落地，后端复用现有 Express + Prisma + PostgreSQL 并上国内云，完成微信登录与小程序备案，先交付 MVP 核心场景。

## 背景

- 现有：H5（React 19 + antd-mobile）+ Express/Prisma/PG，功能已较完整（点菜、总单、管理、图片、排序）。
- 目标：微信内原生小程序体验；不推翻后端，重写前端。

## 范围（In Scope）

- 后端上云适配（配置外部化、CORS、健康检查、容器化）。
- 微信登录接入（`wx.login` → 后端换取 `openid`，绑定现有用户/家庭体系）。
- Taro 小程序骨架（请求层、登录态、路由/标签页）。
- 点菜主流程：菜单（含搜索）、我的单、总单（含划掉/复制）。
- 部署与合规：HTTPS 域名、小程序服务器域名白名单、备案、体验版 → 正式版。

## 范围外（Out of Scope，二期）

- 管理页（菜品/分类/图片/排序）小程序化。
- 图片改云存储（MVP 沿用现有 dataURL/URL 方案）。
- 支付、消息订阅、分享海报等增值能力。

## 关键约束

- 后端 API 契约（`{code,message,data}`、错误码分段）保持不变，前端 Taro 侧重写。
- 保留现有 H5，与小程序并存（共用后端）。
- 小程序主包 ≤ 2MB（必要时分包）。
- **上线路径：微信云托管**（免买服务器、免域名备案，按量付费家庭用量≈0）；开发期用测试号 + 内网穿透零成本推进。
- 云托管环境数据库为 MySQL：上线前 Prisma provider 由 postgres 切 mysql（上线前置项）。

## 验收标准

- [ ] 小程序体验版可在微信开发者工具/真机打开，完成微信登录并进入点菜页。
- [ ] 菜单/我的单/总单三 Tab 与 H5 功能对齐（点菜、数量、划掉、复制清单）。
- [ ] 后端在云环境用环境变量启动，`GET /api/v1/healthz` 正常。
- [ ] 小程序请求全部走已配置的 HTTPS 服务器域名。
- [ ] 小程序备案提交（或备案启动），体验版可用。
- [ ] 现有 H5 不受影响，测试全绿。

## Notes

- 路线决策：Taro（React）/ 国内云 + 备案 / 本期 MVP。
- 管理页与云存储留二期，避免本期过长。
