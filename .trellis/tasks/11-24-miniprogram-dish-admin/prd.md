# 小程序菜品/分类管理（管理员）· PRD

> 父任务：11-23-miniprogram（小程序化改造）
> 定位：把 H5 AdminMenu 的菜品/分类维护能力带入小程序，做饭的人手机上就能维护菜单。

## 背景

小程序 MVP 只有「菜单浏览/我的单/总单」，菜品与分类的维护需回到电脑用 H5 管理页。家庭场景中做饭的人（管理员）希望在手机上直接增改菜品。

## 目标

家庭管理员在微信内完成菜单的全部日常维护，无需打开 H5。

## 用户与权限

- **管理员（ADMIN）**：可见并使用全部管理功能
- **普通成员（MEMBER）**：不可见管理入口；直接访问页面 URL 被守卫弹回（后端接口本身已有 requireAdmin 保护）

## 功能需求

### F1 管理入口

- 「我的」Tab 内新增「菜品管理」行，仅 `member.role === 'ADMIN'` 时渲染
- 点击进入 `pages/admin/index`

### F2 菜品管理页（pages/admin/index）

- 按分类分组的菜品列表；每行显示：图片缩略（无图占位）、名称、描述单行、启用状态
- 操作：
  - **新增菜品**：弹层表单（名称必填、描述选填、图片选传、所属分类下拉）
  - **编辑菜品**：同表单，预填现值
  - **删除菜品**：二次确认；提示「历史点菜记录不受影响」（快照机制）
  - **排序**：同分类内「上移/下移」按钮（简化，不做拖拽）
- 列表下拉刷新

### F3 分类管理

- 菜品管理页顶部「分类管理」入口或分区，能力：新增（名称）、编辑（名称）、删除（二次确认；含菜品的分类由后端拒绝并提示）、排序（上移/下移）

### F4 图片上传

- 复用后端现有图片接口（与 H5 同源），端上用 `Taro.uploadFile` 封装，带 token

### 不做（本任务外）

- 成员角色管理界面（后端接口已在，二期）
- 拖拽排序、批量操作
- 深色模式

## 验收标准

1. ADMIN 在「我的」可见入口并进入管理页；MEMBER 不可见入口
2. 非 ADMIN 直接访问 `pages/admin/index` 被守卫弹回菜单页
3. 新增分类后，菜单页出现该分类（空分组）
4. 新增菜品（含/不含图片）后，菜单页对应分类下可见
5. 编辑菜品名称/描述/图片后，菜单页即时反映
6. 删除菜品后菜单页消失，且「总单」中历史记录不受影响
7. 删除非空分类被后端拒绝并有明确提示
8. 分类/菜品上移下移后，菜单页顺序同步变化
9. 所有写操作后列表无需重进页面即刷新

## 技术边界

- 后端零改动（接口齐全：dishes/categories 的 CRUD + sort + 图片上传，均有 requireAdmin 保护）
- 前端：新增 `pages/admin`、扩展 `services/api.ts`、扩展 `utils/guard.ts`、「我的」页加入口
